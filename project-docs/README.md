# راهنمای فنی پروژه

این پوشه مستندات نگه‌داری و توسعهٔ پروژه را بر اساس کد موجود در مخزن نگه می‌دارد. مستندات برای استفادهٔ توسعه‌دهنده و عامل هوش مصنوعی نوشته شده‌اند: پیش از هر تغییر، فایل ماژول مرتبط و سپس [معماری کلی](01-architecture.md) را بخوانید.

## قواعد نگه‌داری مستندات

- منبع نهایی حقیقت، کد و schema فعلی است؛ این مستندات جای آن‌ها را نمی‌گیرد.
- مسیرهای ذکرشده نسبت به ریشهٔ مخزن هستند.
- تفاوت میان «رفتار مشاهده‌شده در کد» و «ریسک/پیشنهاد» در هر فایل جدا شده است.
- هر تغییر در جدول‌ها، APIها، وضعیت‌های گردش‌کار، مجوزها یا اتصال ماژول‌ها باید هم‌زمان در سند مربوطه ثبت شود.
- برای migrationها، دادهٔ production را حذف یا بازسازی نکنید. تغییر schema باید افزایشی، قابل تکرار و دارای `IF NOT EXISTS` یا سازوکار idempotent مناسب باشد.

## شروع توسعه

1. سند ماژول هدف را بخوانید و وابستگی‌هایش را دنبال کنید.
2. برای رفتار تجاری، اول `src/lib/services/` و سپس handler API را بررسی کنید؛ UI به‌تنهایی مرجع قانون تجاری نیست.
3. schema در `src/db/schema.ts` و migrationها در `drizzle/` را با هم بررسی کنید.
4. مجوزها باید هم در صفحهٔ سروری و هم در API اعمال شوند؛ مخفی‌کردن دکمه در UI کنترل دسترسی نیست.
5. پس از تغییر، سند ماژول و این نقشه را هم‌زمان به‌روز کنید.

## وضعیت پوشش

این نسخه نقشهٔ سراسری و تفکیک ماژول‌ها را بر اساس ساختار فعلی مخزن ثبت می‌کند. بخش «ضعف‌ها و ریسک‌ها» موارد مشاهده‌شده یا فرضیه‌هایی است که برای توسعهٔ بعدی نیاز به تصمیم/تأیید دارند؛ این موارد به‌تنهایی اثبات نقص production نیستند.

آخرین بازبینی تفصیلی در ۲۰۲۶-۱۰-۱۱ انجام شد. در این نوبت، فرم محصول و محدودیت‌های ورودی، جریان Checkout و آدرس/حمل/پرداخت، ثبت POS و خروجی فاکتور/لیبل/فهرست فروش اخیر، انواع رسید خرید تکی و چندقلمی/امانی/تعدیل/حواله، تسویهٔ صاحب کالا، تبدیل بسته‌بندی، کدینگ و گزارش‌های حسابداری با سرویس‌ها و صفحه‌های متناظر تطبیق داده شدند. همچنین مرجوعی آنلاین و POS، برگشت سند و قالب روکش، scope/consent و زمان‌بندی کمپین‌ها، محدودیت‌های تخفیف، و گردش نویسنده/بازبین وبلاگ و SEO/robots جزئی‌تر ثبت شدند. وجود timer داخلی ۶۰ثانیه‌ای برای اجرای کمپین‌ها نیز ثبت شد؛ اجرای پایدار آن در چند replica و صحت posting refund همچنان نیاز به تأیید عملیاتی/مالی دارند. این بازبینی مستندات است و اجرای تست یا صحت دادهٔ production را ادعا نمی‌کند؛ کد و migrationها همچنان مرجع نهایی رفتار اجرایی‌اند.
در بازبینی پنل کاربر نیز فهرست واقعی `CUSTOMER_NAV` با routeها تطبیق داده شد؛ dashboard، صفحات جزئیات سفارش و پشتیبانی/تأمین، برداشت از کیف پول مشتری، اطلاعات بانکی، مدیریت نشست، اعلان‌های محصول و تفاوت دعوت با affiliate به سندهای دامنه اضافه شدند.

**تفسیر وضعیت:** بخش «امکانات/ساختار» خلاصهٔ مشاهده‌شده از کد است؛ بخش «معیارهای پذیرش» مشخص می‌کند تغییر آینده چه رفتاری باید داشته باشد و به معنی آزمون یا تأیید همهٔ این رفتارها در production نیست. برای اختلاف‌های محصول/طراحی که از کد قابل استنتاج نیستند، [فهرست شکاف‌های مشخصات](modules/21-specification-gaps.md) را ببینید.
