# قالب‌های محتوایی وبلاگ و تألیف چندنقشی

## وضعیت

مرحلهٔ ۲۶ نقشهٔ راه تکمیل شده است. مقاله‌ها سه قالب دارند: متنی، ویدیویی و صوتی/پادکست. گردش کار نویسنده و بازبین نیز در پنل و سمت سرور اجرا می‌شود.

## رفتار پیاده‌سازی‌شده

- فرم ایجاد و ویرایش مقاله، انتخاب نوع محتوا و بارگذاری فایل ویدئو یا صوت را ارائه می‌دهد. ویدئوهای MP4/WebM و فایل‌های صوتی MP3/WAV/OGG با محدودیت ۴۰ مگابایت پذیرفته می‌شوند.
- محتوای متنی برای قالب متنی لازم است. در مقاله ویدیویی یا صوتی می‌توان خلاصه یا متن پیاده‌سازی‌شده را هم ثبت کرد، اما اجباری نیست.
- بازیکن صوت/ویدئو در صفحهٔ مقاله قرار می‌گیرد. فایل فقط زمانی بدون نشست قابل دریافت است که به مقالهٔ منتشرشده و فعال متصل باشد؛ فایل مقاله‌های پیش‌نویس یا حذف‌شده از مسیر عمومی قابل مشاهده نیست.
- وضعیت مقاله‌ها شامل پیش‌نویس، در انتظار بازبینی و منتشرشده است. نویسنده می‌تواند پیش‌نویس ذخیره کند یا آن را برای بازبینی بفرستد. بازبین مجاز می‌تواند انتشار را تأیید کند یا با یادداشت، مقاله را برای اصلاح به نویسنده برگرداند.
- مجوز مستقل `BLOG_PUBLISH` برای بازبینی و انتشار افزوده شد. دارندهٔ `PRODUCTS_EDIT` می‌تواند مقاله بسازد، اما بدون `BLOG_PUBLISH` نمی‌تواند مستقیم منتشر کند؛ در ویرایش نیز فقط به نوشته‌های خودش دسترسی دارد. مدیر دسترسی می‌تواند مجوز جدید را در نقش یا گروه بازبینان فعال کند.
- بررسی مجوز و مالکیت مقاله در API سمت سرور انجام می‌شود؛ پنهان کردن دکمه در رابط کاربری تنها کنترل دسترسی نیست. اقدام‌های ارسال، اصلاح، تأیید و انتشار در audit ثبت می‌شوند.
- مقاله‌های موجود مقدار پیش‌فرض `text` می‌گیرند. هیچ متن، وضعیت انتشار، نویسنده، تاریخ انتشار، شناسه یا پیوند مقاله‌ای پاک یا بازنویسی نشده است.

## پایگاه داده و ایمنی انتشار

Migration افزایشی `drizzle/0059_blog_content_workflow.sql` ستون‌های نوع محتوا، شناسه رسانه و یادداشت/زمان/بازبین را با `ADD COLUMN IF NOT EXISTS` و یک ایندکس صف بازبینی اضافه می‌کند. روی دیتابیس توسعهٔ محلی با نام `organito` در `localhost:5430` اجرا شد. این migration روی production اجرا نشده است و هیچ دستور حذف داده یا تغییر دسته‌جمعی وضعیت مقاله‌ها ندارد.

مجوز `BLOG_PUBLISH` از registry فعلی دسترسی‌ها خوانده می‌شود و ساختار `access_roles` نیازی به migration جداگانه ندارد. نقش‌های قبلی به‌طور خودکار به انتشار مقاله دسترسی نمی‌گیرند؛ مدیر باید این مجوز را به نقش بازبینان موردنظر تخصیص دهد. مدیر کل که همهٔ مجوزها را دارد، از ابتدا بازبین مقاله است.

## بررسی و دمو

- TypeScript: `tsc --noEmit` موفق بود.
- `git diff --check` موفق بود.
- Chrome روی `http://localhost:3003/admin/blog` به صفحهٔ ورود هدایت شد، چون نشست مدیر محلی فعال نیست. بعد از ورود مدیر، همان نشانی صف بازبینی و فرم مقاله را نمایش می‌دهد؛ نیازی به ایجاد دادهٔ آزمایشی روی محتوای واقعی نبود.
- migration runner کامل عمداً اجرا نشد؛ در دیتابیس توسعهٔ قدیمی، migration قبلی `0010_media_library.sql` به ستون حذف‌شدهٔ `media.data` وابسته است. فقط SQL مستقل و افزایشی مرحلهٔ ۲۶ اعمال شد.
