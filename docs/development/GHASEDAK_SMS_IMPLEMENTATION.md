# توسعه ارائه‌دهنده پیامک قاصدک

**تاریخ:** ۶ اکتبر ۲۰۲۶  
**مرحله:** مورد ۶ گزارش شکاف‌های ویماشاپ — اولین ارائه‌دهندهٔ افزوده‌شده

## آنچه اضافه شد

- قاصدک در تنظیمات پنل مدیریت پیامک قابل انتخاب است. کلید API از فیلد مشترک تنظیمات عمومی پیامک خوانده می‌شود و مقدار ثبت‌شده در رابط کاربری پنهان می‌ماند.
- ارسال به API رسمی `SendSingleSMS` متصل شد؛ متن کامل پیام رندرشده ارسال می‌شود، بنابراین الگوهای رویداد فعلی و متغیرهایی مانند کد، نام فروشگاه و لینک بدون ثبت Pattern ID قاصدک قابل استفاده‌اند.
- شماره خط از تنظیم «شماره خط / Line Number» خوانده می‌شود. اگر تنظیم نشده باشد، متغیر محیطی `GHASEDAK_LINE_NUMBER` به‌عنوان جایگزین استفاده می‌شود؛ کلید محیطی جایگزین `GHASEDAK_API_KEY` است.
- پاسخ موفق فقط وقتی `IsSuccess` و `StatusCode=200` در پاسخ سرویس تأیید شوند موفق ثبت می‌شود؛ متن پاسخ محدودشدهٔ سرویس در گزارش پیامک ذخیره می‌شود.
- شناسهٔ `clientReferenceId` در retryهای خودکار یک ارسال ثابت می‌ماند تا امکان تشخیص/جلوگیری از تکرار در سرویس مقصد فراهم باشد.
- قاصدک در مسیر ارسال پیامک مستقیم مدیر، رویدادهای باشگاه و تنظیمات مستقل پیامکی تأمین‌کننده نیز پشتیبانی می‌شود.
- API ذخیره تنظیمات باشگاه فروشنده، انتخاب قاصدک را می‌پذیرد.

## محدودیت‌ها و نکات عملیاتی

- پیش از ارسال واقعی، حساب قاصدک باید دسترسی API، اعتبار کافی و خط ارسال مجاز داشته باشد. این مرحله هیچ پیام واقعی ارسال نکرده است.
- قاصدک در این اتصال از ارسال متنی عمومی استفاده می‌کند؛ شناسه‌های قالبی SMS.ir یا کاوه‌نگار به آن ارسال نمی‌شوند.
- دکمهٔ «ارسال پیامک با الگو» در پنل مدیریت مسیر آزمون موجود را به کار می‌گیرد؛ اجرای آن پیام واقعی به شمارهٔ واردشده می‌فرستد و برای همین صرفاً پیاده‌سازی شده و در این توسعه فراخوانی نشده است.

## مرحله بعدی

افزودن **ملی‌پیامک** به‌عنوان دومین ارائه‌دهنده از فهرست این شکاف: تنظیم API Key و شماره خط، ارسال متن متغیر، تحلیل پاسخ موفق/ناموفق و ثبت در گزارش مشترک؛ سپس توسعه تا مدیانا و ippanel.
