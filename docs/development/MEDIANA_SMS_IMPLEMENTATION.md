# توسعه ارائه‌دهنده پیامک مدیانا

**تاریخ:** ۶ اکتبر ۲۰۲۶  
**مرحله:** مورد ۶ گزارش شکاف‌های ویماشاپ — سومین ارائه‌دهندهٔ افزوده‌شده

## آنچه اضافه شد

- مدیانا در تنظیمات مرکزی پیامک و تنظیمات پنل اختصاصی باشگاه فروشنده قابل انتخاب است.
- ارسال متن با API رسمی `POST /sms/v1/send/sms` پیاده‌سازی شد. درخواست شامل `recipients`, `messageText` و خط فرستنده از تنظیم `smsSender` است؛ در نبود خط اختصاصی، نوع ارسال اطلاع‌رسانی (`Informational`) انتخاب می‌شود.
- کلید API در هدر `X-API-KEY` فرستاده می‌شود. برای تنظیم از محیط، متغیر `MEDIANA_API_KEY` پشتیبانی می‌شود.
- خطاهای HTTP، `meta.code` غیر از `OK` و پاسخ `data.succeed=false` به‌عنوان شکست ثبت می‌شوند. اگر پاسخ موفق بدنه نداشته باشد، وضعیت HTTP در گزارش ارسال ذخیره می‌شود.
- مسیرهای پیامک رویدادی، ارسال دستی، retry گزارش، ارسال مستقیم رویدادهای مناسبتی و ارسال باشگاه فروشنده از مدیانا استفاده می‌کنند.
- ارائه‌دهنده به فهرست مجاز API تنظیمات افزوده شد؛ تنظیمات باشگاه فروشنده از کلید و خط مستقل خودش استفاده می‌کند.
- ارسال پترن تأییدشده از `/sms/v1/send/pattern` با `patternCode` و placeholderهای نام‌دار نیز در [گزارش عملیاتی‌سازی الگوها](SMS_PATTERN_OPERATIONAL_IMPLEMENTATION.md) افزوده شده است.

## محدودیت‌ها و نکات عملیاتی

- در مستند رسمی مدیانا برای پیام عادی، پاسخ موفق می‌تواند بدون بدنه باشد؛ بنابراین موفقیت بر مبنای HTTP و نبودن کد خطای API تشخیص داده می‌شود. ارسال واقعی برای راستی‌آزمایی حسابی انجام نشده است.
- گزارش پیگیری تحویل بر اساس `smsItemId` هنوز متصل نشده است.
- در صورت timeout پس از پذیرش پیام توسط سرویس، نتیجه می‌تواند نامشخص باشد؛ API ارسال عادی در مستندات شناسه idempotency اعلام نمی‌کند.

## مرحله بعدی

افزودن **ippanel** به‌عنوان چهارمین ارائه‌دهنده از فهرست این شکاف: کلید API و خط ارسال، endpoint ارسال عادی، پردازش کد پاسخ و اتصال به تنظیمات مرکزی و باشگاه فروشنده.
