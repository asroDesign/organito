# پیاده‌سازی منوساز چندجایگاهی

## محدوده

مدیریت منوهای عمومی سایت برای سه جایگاه مستقل هدر دسکتاپ، فوتر و موبایل در مسیر `/admin/menus` اضافه شد. پنل هر جایگاه را جداگانه نشان می‌دهد و ساخت، ویرایش، فعال/غیرفعال‌سازی، حذف نرم، جابه‌جایی با drag-and-drop و مرتب‌سازی با دکمه‌های جهت‌دار را پشتیبانی می‌کند. هر منو تا سه سطح زیرمنو دارد؛ آیتم فوتر می‌تواند در یک ستون گروه‌بندی شود.

پیوندهای داخلی و آدرس HTTPS پذیرفته می‌شوند. بازشدن لینک در زبانه جدید تنظیم‌پذیر است و با `noopener noreferrer` باز می‌شود. API نشانی‌های `javascript:`, `data:` و آدرس‌های protocol-relative را رد می‌کند، والد را به همان جایگاه محدود می‌کند، چرخه والد و عمق بیش از سه سطح را نمی‌پذیرد و حذف والد، فرزندانش را نیز نرم حذف می‌کند. تغییرها در audit log ثبت و صفحه عمومی برای بازنمایی تازه می‌شود.

هدر دسکتاپ زیرمنوهای بازشونده و موبایل منوی باز/بسته‌شونده با زیرمنوهای مستقل دارد. اگر منوی هدر هنوز خالی باشد، پیوندهای پیش‌فرض فعلی فروشگاه نمایش داده می‌شوند؛ این کمک می‌کند پس از نصب migration ظاهر فعلی حفظ شود. خاموش کردن جایگاه هدر یا موبایل نمایش همان منو را می‌بندد. فوتر از ساختار گروه‌بندی قبلی استفاده می‌کند.

## داده و مهاجرت

فایل افزایشی `drizzle/0053_site_menus.sql` دو جدول منو و آیتم منو می‌سازد و سه جایگاه را به شکل idempotent seed می‌کند. پیوندهای جدول `footer_links` با شناسه منبع منتقل می‌شوند تا اجرای دوبارهٔ migration ردیف تکراری نسازد. جدول قدیمی و داده‌هایش دست‌نخورده باقی می‌مانند. migration روی دیتابیس توسعهٔ محلی `organito` اجرا شد؛ شمار پیوند قدیمی فوتر صفر بود، پس داده‌ای برای انتقال وجود نداشت. هیچ رکورد آزمایشی به منوها اضافه نشد.

این migration روی دیتابیس production اجرا نشده است. انتشار نسخه باید migration افزایشی 0053 را روی همان مقصد اجرا کند.

## بررسی

`yarn typecheck` و `git diff --check` موفق شدند. سرور موجود روی پورت ۳۰۰۰ نسخهٔ فعلی را نداشت؛ دمو با سرور توسعهٔ پروژه روی پورت ۳۰۰۳ و در Chrome باز شد. برای کنترل محدودیت watcher محیط، اجرای dev از polling استفاده می‌کند. صفحهٔ `/admin/menus` در دمو آماده است و هیچ آیتم آزمایشی ذخیره نشده است.
