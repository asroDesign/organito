# استعلام تلفنی قیمت و موجودی محصول

## رفتار پیاده‌سازی‌شده

- مدیر هنگام ساخت یا ویرایش محصول می‌تواند فروش با استعلام را برای کل محصول فعال کند. در ویرایش هر تنوع نیز تنظیم مستقل وجود دارد.
- قیمت، تخفیف و موجودی دقیق محصول/تنوع استعلامی در کارت کالا، صفحه محصول، مقایسه، Quick View، تاریخچه قیمت و پاسخ‌های عمومی API نمایش داده نمی‌شود.
- به‌جای افزودن به سبد، مشتری فرم مودال درخواست تماس را با نام، موبایل، توضیح اختیاری و رضایت صریح ارسال می‌کند. برای مشتری واردشده، نام و موبایل اولیه از حساب کاربری خوانده می‌شوند.
- API شماره موبایل را نرمال و اعتبارسنجی می‌کند، درخواست‌های پرتکرار را بر اساس IP و شماره موبایل محدود می‌کند، محصول/تنوع و وضعیت استعلام را دوباره می‌سنجد و یک شماره پیگیری یکتا می‌سازد.
- پنل `/admin/product-inquiries` فهرست صفحه‌بندی‌شده، جستجو، فیلتر وضعیت و شمارنده‌ها دارد. مدیر می‌تواند تماس بگیرد، مسئول تعیین کند، یادداشت داخلی ثبت کند و وضعیت را به جدید، تماس‌گرفته‌شده، بسته‌شده یا تبدیل‌شده به سفارش تغییر دهد.
- تبدیل به سفارش تنها وقتی پذیرفته می‌شود که سفارش موجود باشد و شماره موبایل مشتری آن با موبایل استعلام تطبیق کند. این قابلیت سفارش جدید یا پرداخت را به‌صورت خودکار نمی‌سازد.
- سرور هنگام محاسبه و ثبت سبد خرید نیز محصول و تنوع استعلامی را رد می‌کند؛ مخفی‌کردن دکمه در مرورگر به‌تنهایی مبنای کنترل نیست.

## داده و مهاجرت

`drizzle/0054_product_price_inquiries.sql` دو ستون بولی افزایشی برای محصول و تنوع و جدول درخواست‌ها و indexهای لازم را می‌افزاید. migration با `IF NOT EXISTS` نوشته شده و هیچ جدول یا داده موجود را حذف یا بازنویسی نمی‌کند. روی دیتابیس توسعه محلی `organito` اجرا شد؛ جدول تازه خالی است و migration روی production اجرا نشده است.

## مسیرهای دمو

- مدیریت و پیگیری: `/admin/product-inquiries`
- تنظیم محصول: `/admin/products/new` یا ویرایش محصول موجود، در اطلاعات پایه/تنوع‌ها
- فرم مشتری: صفحه عمومی محصولی که مدیر حالت استعلام را برای آن فعال کرده باشد

دموی Chrome در `http://localhost:3003/admin/product-inquiries` باز است. برای حفظ اطلاعات فروشگاه، محصول آزمایشی ثبت یا محصول موجود تغییر داده نشد؛ فهرست استعلام‌ها در حال حاضر خالی است.

## بررسی

`yarn typecheck` و `git diff --check` اجرا شدند. درخواست واقعی استعلام آزمایشی ثبت نشد.

## گام بعدی

گزارش شکاف قابلیت‌ها مرحله ۲۰ را برای تحلیل پیشرفته مسیر مشتری پیشنهاد می‌کند: ثبت رخدادهای صفحه و قیف بازدید تا خرید، منبع/کانال ورود و گزارش نرخ تبدیل با حفظ حریم خصوصی و بدون کندکردن تجربه خرید. پیش از فعال‌سازی باید سیاست نگهداری/ناشناس‌سازی و رفتار رضایت کاربر روشن باشد.
