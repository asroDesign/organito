# گزارش پیاده‌سازی ورود اطلاعات محصول دیجی‌کالا

**تاریخ:** ۷ اکتبر ۲۰۲۶  
**مورد نقشه راه:** ۱۵ — ورود محصول از دیجی‌کالا  
**وضعیت:** پیاده‌سازی شد؛ دمو در پنل مدیریت آماده است.

## تصمیم درباره منبع داده

در بررسی شرایط رسمی دیجی‌کالا، استفاده از مطالب به هدف غیرتجاری و ذکر منبع محدود شده است ([شرایط و قوانین دیجی‌کالا](https://www.digikala.com/page/terms/)). از آنجا که پروژه فروشگاه تجاری است، واکشی صفحه عمومی دیجی‌کالا، استخراج خودکار متن و دانلود تصویر در این ابزار فعال نشده است. ورود اطلاعات تنها برای محتوایی مناسب است که مدیر مجوز استفاده تجاری از آن را دارد؛ URL/شناسه فقط به‌عنوان ارجاع منبع ثبت می‌شود.

این پیاده‌سازی امکان انتقال دستی و بازبینی‌شده اطلاعات دارای مجوز را فراهم می‌کند. اتصال آینده به API رسمی یا feed دارای مجوز می‌تواند جایگزین ورود JSON شود، پس از دریافت مستندات و اعتبارنامه مجاز.

## تجربه و مسیر کار

- صفحه `/admin/products/import` از منوی «محصولات و محتوا» در دسترس کاربران دارای مجوز `PRODUCTS_CREATE` است.
- مدیر URL رسمی محصول یا شناسه `dkp-...` را وارد می‌کند. آدرس به شکل canonical ذخیره می‌شود و URLهای غیر HTTPS، دامنه‌های مشابه و مسیرهای غیرمحصول رد می‌شوند.
- اطلاعات متنی مجاز به صورت JSON وارد می‌شود. پیش‌نمایش زنده نام فارسی، برند، توضیح کوتاه و مشخصات را بدون اجرای HTML نمایش می‌دهد.
- انتخاب دسته‌بندی اختیاری است. API وجود دسته انتخاب‌شده را بررسی می‌کند.
- تأیید checkbox مجوز استفاده تجاری از محتوای واردشده الزامی است.
- با ثبت، محصول مرکزی به حالت `draft` ساخته می‌شود و کاربر به ویرایش کامل محصول می‌رود. اطلاعات منبع در صفحه جزئیات ادمین دیده می‌شود.

فیلدهای قابل انتقال: `nameFa` و `brand` الزامی‌اند؛ `nameEn`، `manufacturer`، `country`، `shortDesc`، `description` و `specs` اختیاری‌اند. مشخصات می‌توانند از کلیدهای `k`/`v` یا `name`/`value` استفاده کنند.

## محافظت از کاتالوگ و داده فروش

- قیمت و قیمت قبل از تخفیف صفر تنظیم می‌شوند؛ قیمت‌های منبع منتقل نمی‌شوند.
- موجودی و تنوع‌ها وارد نمی‌شوند؛ تصاویر یا رسانه منبع بارگیری نمی‌شود.
- انتشار خودکار وجود ندارد. انتشار، قیمت‌گذاری، مشخصات اصالت، تصاویر و موجودی باید در ویرایش محصول تکمیل شوند.
- شناسه منبع و SKU تولیدشده یکتا هستند؛ ورود دوباره همان محصول با خطای تعارض متوقف می‌شود.
- ایجاد محصول از مسیر سرویس موجود `saveProduct` استفاده می‌کند تا ثبت تاریخچه قیمت، ممیزی و قواعد کاتالوگ حفظ شود.

## فایل‌ها و پایگاه داده

- رابط: `src/components/DigikalaProductImporter.tsx`
- صفحه مدیریت: `src/app/admin/products/import/page.tsx`
- API و بررسی ورودی: `src/lib/api/product-import.ts`
- ردیابی منبع در مدل محصول: `src/db/schema.ts`
- API تجمیعی: `src/app/api/[...path]/route.ts`
- نمایش منبع در جزئیات: `src/app/admin/products/[id]/page.tsx`
- مهاجرت افزایشی: `drizzle/0050_digikala_product_import.sql`

Migration فقط ستون‌های nullable `external_source_url` و `external_source_id` و یک unique index برای جلوگیری از پیوند هم‌زمان یک منبع به چند محصول اضافه می‌کند. روی دیتابیس محلی `organito` در تراکنش با قفل advisory اجرا شد؛ پیش از افزودن index، نبود شناسه منبع تکراری کنترل شد. دیتابیس ۴۷ محصول موجود داشت و ردیف‌ها، قیمت‌ها و موجودی آن‌ها تغییر نکردند.
